You are taking Lumina from "code complete" to "live on the App Store".

Lumina is a SwiftUI 5 / iOS 26 astrology app. A Node service (Fastify +
`astronomy-engine`) computes every chart, transit, reading and compatibility
score; the app is a client. Subscriptions run through RevenueCat. The repo is
`Wrexist/Lumina`.

## How to work

**You cannot compile Swift.** There is no Xcode, no simulator, no toolchain on
Linux. CI's `macos-15` job is the only thing that builds this project. Load the
`verify-without-a-mac` skill before claiming any Swift change works. Run
`bash scripts/local_checks.sh` before every push — it catches lint limits, JSON,
plists, metadata and the backend.

**The accuracy rule matters more than anything else here.** This project's
recurring defect is shipped copy describing an app that doesn't exist — it has
been found and fixed *seven* times across the app name, keywords, Help articles,
the glossary, a preview, a screenshot, and the Human Design screen. Three guards
now exist (`ReleaseAccuracyTests`, `scripts/aso_lint.py`, and a screenshot suite
that renders real components). **Never** add a claim about a feature without
checking the binary has it, and when you fix a claim, add the test that stops it
coming back. Palm reading is *not* in this build.

**Never invent numbers.** No search volumes without Apple Search Ads data, no
pricing without reading the vendor's page. If you cannot verify it, say so.

## What only a human can do

Do not attempt these; ask and wait. They need a browser session, a card, or an
identity you do not have:

- Any account creation or sign-in (Apple, RevenueCat, Fly, OneSignal, Supabase)
- Anything inside App Store Connect or the Apple Developer portal
- Reading or entering secret values
- **Triggering a workflow.** The agent token lacks `actions: write`; a
  `workflow_dispatch` call returns 403. Ask the human to press Run workflow.

Everything else — repo changes, CI diagnosis, metadata, docs, verification — is
yours. Do it rather than describing it.

# Phases

Each phase has a gate. Do not start the next one until the gate is met.

## Phase 0 — Merge and verify

1. Merge `claude/pre-launch-audit-checklist-7dwc53` into `main` (both commits are
   already CI-green; open a PR only if the human asks).
2. Confirm CI is green on `main` afterwards.

**Gate:** `main` green, and `git log` shows both commits.

## Phase 1 — Backend live

Human does the account work; you verify and fix everything else.

1. **Ask the human to rotate the Anthropic key first** — one is in this repo's git
   history. Delete (not disable) at console.anthropic.com, create
   `lumina-backend-prod`, set a monthly spend cap, and `fly secrets set
   ANTHROPIC_API_KEY=... --app lumina-ephemeris`.
2. Ask them to add three GitHub secrets: `FLY_API_TOKEN` (from
   `fly tokens create deploy -a lumina-ephemeris`), `SWISS_EPH_API_SECRET` (must
   equal the Fly `LUMINA_API_SECRET` **character for character** — a mismatch is a
   401 on every request, which looks like a broken app, not a config error), and
   `SWISS_EPH_SERVICE_URL` = `https://lumina-ephemeris.fly.dev` (https, no
   trailing slash).
3. Ask them to run **Actions → backend-deploy → Run workflow**.
4. Verify yourself: `curl https://lumina-ephemeris.fly.dev/health` returns
   `{"status":"ok"}`.

If the human would rather not pay for Fly, the backend has **zero** Fly-specific
code — a plain Dockerfile on `$PORT`. Moving means a new deploy workflow, the
smoke-test URL, and `SWISS_EPH_SERVICE_URL`. One hard constraint when choosing:
`docs/NAVIGATION.md` §12 requires an error state beyond ten seconds, and the
client now retries within that budget (4s + 1s + 5s), so **any host whose cold
start exceeds ~10s is incompatible regardless of price.** Verify a candidate's
current cold-start behaviour and pricing by reading its docs — do not assert
either from memory.

**Gate:** `/health` returns ok from a machine that is not the deploy runner.

## Phase 2 — RevenueCat

Entirely human, in a browser. Your job is to check their work.

Give them these exact identifiers and explain that all four are strings the app
looks up — a typo fails silently, showing an empty paywall rather than an error:

| Thing | Value |
|---|---|
| Entitlement identifier | `lumina_plus` |
| Monthly package | `$rc_monthly` |
| Annual package | `$rc_annual` |
| Offering | must be marked **Current** |

Product IDs (`lumina_plus_monthly`, `lumina_plus_annual`) are created in App Store
Connect first, priced, given display names and review descriptions from
`metadata/app-store.json` → `in_app_purchases`, and screenshotted. **No weekly
tier** — Apple is rejecting those in this category.

Then `REVENUECAT_API_KEY_IOS` = the public iOS key (starts `appl_`).

**Gate:** the human confirms the offering is Current and shows both packages.

## Phase 3 — First TestFlight build

1. Ask the human to tick **App Groups** (`group.app.lumina.ios`), **Push
   Notifications** and **Sign In with Apple** on `app.lumina.ios` at
   developer.apple.com. Without the app group the widget ships blank.
2. Ask them to run **Actions → ios-testflight → Run workflow**, build number
   blank (the run number is used, and only ever increases).
3. If it fails, diagnose from the logs and push a fix. The lane lints and runs the
   full test suite before archiving, so a red run is usually a real defect.

**Gate:** build processed in App Store Connect.

## Phase 4 — Device QA

Only a human with a real iPhone can do this, and it is the phase most likely to
find something. Ask them to check, and act on what comes back:

- Charts actually load (proves the backend wiring end to end)
- A sandbox purchase completes and unlocks Human Design
- The home-screen widget renders rather than staying blank
- The onboarding rating screen appears and Apple's card follows the stars
- Account deletion completes

**Gate:** all five pass, or the failures are fixed and a new build is up.

## Phase 5 — App Store Connect listing

1. Run `python3 scripts/aso_lint.py` — it must pass.
2. `python3 scripts/aso_lint.py --print` gives paste-ready blocks with character
   counts. `--fastlane` regenerates `fastlane/metadata/`, which `fastlane deliver`
   uploads in one command — prefer that over fifteen manual pastes.
3. Screenshots: download the `app-store-screenshots` artifact from the latest
   green CI run. Five frames, already at Apple's required size.
4. Remaining forms: privacy labels matching `Lumina/Resources/PrivacyInfo.xcprivacy`
   (see `docs/aso/PRIVACY-LABELS.md`), age rating → **4+**, review notes (already
   written in `metadata/app-store.json` → `review.notes`, including the
   explanation of the onboarding rating prompt), export compliance (should not
   even be asked — `ITSAppUsesNonExemptEncryption: false` is in the Info.plist).

**Gate:** `docs/aso/METADATA-PACK.md` §10 fully ticked.

Add for Review, attach the build, **turn phased release on** (free kill switch).

## Phase 7 — After it's live

- Watch the first twenty ratings; they set the average for months. If they cluster
  on one complaint, that complaint is 1.1.
- Read `docs/aso/RATINGS.md` before touching the rating prompts. If the onboarding
  stars are ever rejected under Guideline 1.1.7, the fix is to drop the stars and
  keep the Today ask — **never** make Apple's card conditional on the rating.
- `docs/aso/SEARCH-ADS.md` has the keyword-measurement plan. Keyword fields can
  only change with a new version, so swap about five per release; a wholesale
  rewrite makes the numbers unattributable.

# Things that cost hours to rediscover

- **CI runs come in pairs.** Every push produces a `push` run and a
  `pull_request` run with the same SHA; the commit-keyed concurrency group
  cancels one. A `cancelled` sibling is **not** a failure — read the survivor.
- **Job logs are megabytes of base64.** `get_job_logs` will exceed the token cap
  and get written to a file. Parse it with python: filter to lines under ~700
  chars for the human-readable output, and grep for `✖`, `XCTAssert`, or
  `Executed N tests, with M failures` where M > 0.
- **Screenshots come back through the log**, base64 between
  `===SHOT_BEGIN <name>===` / `===SHOT_END===` markers, because artifact storage
  is blocked by the sandbox's egress rules. Strip the per-line timestamp,
  `base64.b64decode`, check the PNG magic bytes.
- **A missing CI run does not mean Actions is broken.** Runs have appeared tens
  of minutes after a push. This project once reported an outage in writing that
  was only queue lag.
- **`MARKETING_VERSION` in `project.yml` must equal `version` in
  `metadata/app-store.json`.** App Store Connect attaches an upload to the App
  Store version matching `CFBundleShortVersionString`; a mismatch means the build
  silently never appears in the build list. `aso_lint.py` now fails on drift.
- **SwiftLint runs `--strict`,** so warnings are errors, and the opt-in list is
  long (`implicit_return`, `sorted_imports`, `type_body_length: 250`,
  `file_length: 400`, custom colour/spacing rules). Read `.swiftlint.yml` before
  writing Swift, and check the rule's source rather than guessing.
- **Swift 6 strict concurrency.** A `View` or a `@MainActor` type makes its
  statics main-actor isolated; pure helpers called from tests need explicit
  `nonisolated`.

# Definition of done

The app is live on the App Store, the backend answers `/health`, a real purchase
completes on a real device, and `python3 scripts/aso_lint.py` passes on `main`.

Report honestly throughout: if a step is blocked, say what is blocking it rather
than working around it silently. If you find a claim in shipped copy that the
binary cannot back, stop and fix it — that is the defect this project keeps
producing, and it is worth interrupting anything else for.
