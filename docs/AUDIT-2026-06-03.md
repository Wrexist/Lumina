> Date: 2026-06-03 · Branch: `claude/adoring-euler-yEDvq` · Auditor: Claude Code
> Scope: every Swift file (`Lumina/`, `LuminaTests/`), the TypeScript backend (`backend/`),
> and all build/CI/lint/config. Cross-checked against `CLAUDE.md`, `ROADMAP.md`,
> `TASK.md`, `LEARNINGS.md`, and `docs/NAVIGATION.md`.

---

## 0. How this was produced

Nine parallel deep-audits, one per area, each reading its files in full and verifying
claims against the specs and (for the backend) against astronomy references. Every
headline bug below was re-confirmed by direct file read. Where an agent's severity
was wrong, it has been recalibrated here (e.g. the "missing GlossaryLink" issue is
**not** a build-break because no glossary CI gate actually exists).

**Bottom line:** the app almost certainly **builds green today** — the code is
unusually disciplined (no force-unwraps / `fatalError` / `print`, no hardcoded
hex/fonts, `@MainActor`/`@Observable`/actor isolation all correct, the ephemeris
math is genuinely correct and tested). The real problems are **runtime correctness,
data-integrity, privacy/security, spec compliance, accessibility, and large swaths of
"claimed-done-but-stubbed" features** — not compilation.

## 3. Top must-fix list (the 15 headline issues)

1. **P0 — Journal inserts blank entries just by opening the tab.** `ReflectHubView.swift:92-93` calls `createTodayEntry()` (insert + save) inside a `NavigationLink` destination builder, which SwiftUI evaluates eagerly during `body`. Every render with no today-entry writes a new empty entry → calendar pollution, duplicate rows, and false progress toward the 3-entry Plus gate.
2. **P0 / SECURITY — Full birth PII in a plaintext QR.** `ShareQRView.swift:103-112` base64-encodes exact birth date, time, and precise lat/lon into `lumina://share/<base64>` that "works with any camera app," while the UI claims "no account info." Base64 is not protection.
3. **P0 / COMPLIANCE — Paywall copy contradicts behavior.** `PaywallOfferView.swift:111` says "we never re-prompt you in the same session," but the sanctioned flow shows the `.rescue` offer in the same session. Either copy or behavior must change (Apple 3.1.2(c) dark-pattern risk).
4. **P1 — Compatibility scores drift every launch.** `CompatibilityScorer.swift:72` uses `String.hashValue` (per-process randomized seed) for jitter, so the persisted `Friend.compatibilityScore` silently changes on every cold start, contradicting its own "stable" contract.
5. **P1 — Reflect Face ID lock never re-locks.** `AppLock.resetSessionUnlocks()` is documented to fire on `scenePhase == .background` but is **never called** — `LuminaApp`/`RootView` don't observe `scenePhase`. Once unlocked, journals stay unlocked for the whole process lifetime, and the lock is bypassable via pushed detail views / deep links.
6. **P1 — The 30%-off rescue paywall never displays.** `OnboardingFlowView.swift:140-144` transitions `.fullScreenCover(item:)` from `.initial` → `.rescue` (non-nil → non-nil), which SwiftUI does not re-present. The headline Phase-2 rescue offer is effectively dead.
7. **P1 — QR share round-trip is broken end-to-end.** Nothing consumes `LuminaDeepLink.acceptShare(payload:)` — there is no base64→`BirthData` decoder and no "add this friend" screen. The receive half of the feature doesn't exist.
8. **P1 — Today hub renders no loading/empty/error/missing-data states.** `TodayViewModel.state` is computed but never read by `TodayHubView`; it unconditionally renders content even with no chart. Violates `NAVIGATION.md` §4.
9. **P1 — Silent fake-chart fallback on real failures.** `TodayViewModel.swift:81-92` (and `BirthChartViewModel`) serve the Stockholm-1990 `sampleChart()` on *any* error, so a real network/server failure shows the user someone else's Big-3 with no error. Gate sample data behind `#if DEBUG`.
10. **P1 — Deep links to `settings`/`help` and links captured during onboarding are dropped.** `AppRouter.handle` sets `pendingPresentation` for tab-less links, but nothing in `MainTabsView` consumes it; and `completeOnboarding()` never replays `pendingDeepLink`.
11. **P1 — Human Design over-reports defined centers.** `HumanDesignActivation.swift:39-41` marks a center "defined" from a *single* activated personality-side gate; real HD requires a full activated channel. This makes a substantive (wrong) claim to the user and violates the project's own HD-honesty rule.
12. **P1 — Latent crash if backend returns ≠12 house cusps.** `ChartWheelView` and `PlanetDetailSheet` index `houses.cusps[(index+1) % 12]` with no count guard → out-of-bounds.
13. **P1 / SECURITY — Anthropic API key ships in the app binary.** `project.yml:68` bakes `LuminaAnthropicAPIKey` into `Info.plist`, and `LuminaAIClient` is designed to call Anthropic directly. The key is trivially extractable from the IPA. LLM calls must go through the backend.
14. **P1 — Backend never converts birth-local-time → UT.** `timeZoneIdentifier` is received and validated but never used; `noonUTOf` also shifts the calendar day for far-east offsets. Correct for the iOS app (sends absolute instants) but silently wrong for the CLI / any other caller.
15. **P1 — No `Assets.xcassets` anywhere.** `project.yml:82-83` references `AppIcon` + `AccentColor`, but no asset catalog exists. Builds with no icon; any TestFlight/App Store upload will reject.

## 4. Findings by area

### 4.1 App shell / routing (`Lumina/App/`)

- **P1 `AppRouter.swift:84-96` + `MainTabsView.swift` — `settings`/`help` deep links never presented.** `handle()` sets `pendingPresentation = .settings` (tab is nil) but `MainTabsView` only opens Settings via the gear button; no consumer reads `pendingPresentation` for tab-less links. `lumina://settings` and `lumina://help` do nothing. *Fix:* in `MainTabsView`, add `.onChange(of: router.pendingPresentation)` that maps `.settings`→`settingsPresented = true`, `.help(topicID:)`→present Help, then clears it.
- **P1 `AppRouter.swift:66-70` — deep link captured during onboarding is dropped.** `completeOnboarding()` doesn't replay `pendingDeepLink`. *Fix:* at the end of `completeOnboarding()`, if `pendingDeepLink != nil`, call `handle(deepLink:)` and clear it.
- **P2/FEATURE `MainTabsView.swift:28-50` — per-tab `NavigationStack` has no typed `NavigationPath` and no persistence.** `TASK.md` Phase 1 wants typed paths + restore via `@AppStorage`. *Fix:* give each tab a `@State NavigationPath`, persist last tab (already done via `selectedTab.didSet`) and path on `scenePhase` change.
- **FEATURE `AppDelegate.swift:11-14` — RevenueCat & OneSignal are TODO stubs.** IAP and push are entirely non-functional. *Fix (when creds land):* `Purchases.configure` + `OneSignal.initialize` here (per `LEARNINGS.md`, not in `LuminaApp.init`).
- **P2 `LuminaTab.swift:31-39` — tab icons are SF Symbols, not the brand glyph set** (`NAVIGATION.md` §2 calls for custom glyphs). FEATURE: ship brand glyphs in the (missing) asset catalog.
- **P3 `LuminaDeepLink.swift:12` — case is `acceptShare(payload: String)` vs the spec's `acceptShare(birthData: BirthData)`.** The string form is actually safer (defer decode to People), but reconcile the spec text.
- **NOTE** `AppRouter` state machine, `AppRouterStorage` protocol-backed `@unchecked Sendable`, and `selectedTab` persistence are all correct and Swift-6-clean.

### 4.2 Design system (`Lumina/Design/`)

- **P2 `LuminaCard.swift:38-40` — Liquid Glass is faked with `.thinMaterial`.** Deployment target is iOS 26 only, so the "compiles on iOS 17 runners" rationale doesn't apply. `CLAUDE.md`/`LEARNINGS.md` explicitly require the native glass API. *Fix:* use `.glassEffect()` / `.glassBackgroundEffect()` on the `.glass` surface.
- **P2 `LuminaTypography.swift:8-13` — fixed point sizes don't scale with Dynamic Type.** `Font.system(size: 40, …)` is non-scaling; `NAVIGATION.md` §17 requires clean Accessibility-XL. *Fix:* use text-style-relative fonts (`.system(.largeTitle, design: .serif)`) or `Font.custom(_:size:relativeTo:)` once fonts land.
- **P2 `LuminaTextField.swift:42` — secure field exposes its text via `.accessibilityValue(text)`.** VoiceOver will read passwords aloud. *Fix:* suppress `accessibilityValue` (or set to a redacted string) when `isSecure`.
- **P2 `LuminaTextField.swift:89-93` + `LuminaButton.swift:74` — no error-red token; errors render in `blush` (#E5C8C2) and the destructive button is `inkBlack`.** Poor contrast and off-spec (`NAVIGATION.md` §5 wants parchment-on-error-red). *Fix:* add `LuminaColors.error` (an accessible red) and use it for error text + destructive fill.
- **P2 Colors — no dark-mode adaptation.** All colors are fixed sRGB; a dark-mode device still shows the parchment light theme. *Fix:* either declare light-only (`UIUserInterfaceStyle = Light` in Info.plist) or add dark variants.
- **P3 `LuminaShadows.swift:46` — dark-mode shadow is `.clear`** (relies on stroke); acceptable but means no elevation cue in dark mode (moot until dark mode exists).
- **P3 `LuminaSkeleton.swift:51` — uses `LuminaSpacing.xs` as a corner radius** instead of `LuminaRadii.xs`; cross-token usage.
- **NOTE** Color hex values match the `CLAUDE.md` spec exactly; spacing/radii tokens are clean; Reduce Motion is honored by `LuminaButton`/`LuminaSkeleton`/`Haptics`; the custom lint rules correctly exclude `Design/Tokens/`.

### 4.3 Onboarding (`Lumina/Features/Onboarding/`)

- **P2 `OnboardingState.swift` — fields persist only on `advance()`/`applyResolvedPlace()`, not on every change.** `NAVIGATION.md` §6 wants per-field persistence; a force-quit mid-step loses the current step's input. *Fix:* call `persist()` from a debounced `didSet`/`.onChange` on each captured field (or persist on `scenePhase` change).
- **P2 `OnboardingScreens.swift:216-251` — the three "What next" cards all call `onPick()` → complete → Today.** "Scan a hand" / "Add a friend" don't route to their named destinations, and the screen also shows a bottom "Take me to Today" primary (multiple equivalent CTAs, §5). *Fix:* set `router.pendingDeepLink` to the chosen destination before completing, or make them visibly a single "continue" choice.
- **P2 `AppRouter.resetForSignOut()` + onboarding — re-onboarding resumes with stale data.** `resetForSignOut` doesn't clear the onboarding snapshot or `UserBirthDataStore`, so a fresh `OnboardingState()` reloads the old snapshot (possibly at `whatNext`). *Fix:* call `OnboardingStorage.clear()` + wipe birth data on sign-out.
- **P2 `ManualBirthPlaceSheet.swift:33` — error text in `blush` (same low-contrast issue).** And the time-zone `Picker(.menu)` lists ~600 IANA zones (poor UX) — prefer a searchable list.
- **P3 `OnboardingState.swift:56` — `stepError` is dead** (the reveal screen uses its own `@State error`).
- **P3 `OnboardingScreens.swift:34-85` — `motivation` is captured but never used** despite "shapes the readings we send" copy. Wire it into personalization/analytics or soften the copy.
- **P3 `OnboardingScreens+Reveal.swift:77` — the computed chart result is discarded**; the Chart tab recomputes from scratch. Consider caching the reveal result.
- **FEATURE** Sign in with Apple, the 14 analytics events, the post-first-reading notification prompt, and inline-error transition animations are all still pending (`TASK.md` Phase 2).
- **NOTE** Resume-on-kill (step granularity), validation gates, MapKit completer Swift-6 isolation, IANA-tz capture, the manual fallback, and the noon/houses-hidden "I'm not sure" path are all correct.
